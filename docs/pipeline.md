## 전체 순서

```
[1] 데이터 확보      Drive 에 OmniFall 28GB (낙상 데이터셋 8종)
[2] 압축 해제        Cauca + EDF + GMDCSA24 = 2.8GB  (/content, 휘발성)
[3] manifest         파일명 파싱 → 1,194 클립          (Drive, 영구)
[4] 키포인트 추출    YOLOv11-pose → (T,17,3) .npy      (Drive, 영구)
[5] 학습 데이터 구성 64프레임 리샘플 + 피험자 split
[6] 모델 6개 비교    rule/cnn1d/lstm/gru/bilstm/stgcn
[7] 카메라 일반화    특정 카메라 held-out 테스트
```

`[4]` 까지 끝나면 세션이 죽어도 안전하다. 학습은 키포인트만 있으면 몇 분이면 된다.

## 왜 키포인트를 미리 뽑아 저장하는가

영상에서 매번 추출하면 모델 하나 학습할 때마다 수십 분이 든다. 한 번 뽑아 `.npy` 로
저장하면 **6개 모델이 같은 데이터를 재사용**한다.

공정한 비교의 조건이기도 하다 — 모든 모델이 정확히 같은 입력을 받아야
성능 차이를 모델 구조 탓으로 돌릴 수 있다.

## Colab 세션 회수 대응

**세션은 예고 없이 사라진다.** 실측으로 두 번 겪었다 (GPU 40분, 유휴 중 1회).
`/content` 는 세션과 함께 소멸하므로 중간 결과를 여기 두면 안 된다.

| 대상 | 위치 | 이유 |
|---|---|---|
| 압축 해제한 영상 2.8GB | `/content` | 재생성 가능, Drive 에 두면 I/O 가 느리다 |
| **manifest** | **Drive** | 작다. 재생성 비용은 낮지만 기준이 흔들리면 안 된다 |
| **키포인트 .npy** | **Drive** | 수십 MB. **추출이 전체 시간의 대부분** |
| 학습 결과 | Drive | 논문 근거 |

키포인트가 Drive 에 있으면 재시작 시 이미 만든 것을 건너뛰고 이어서 시작한다.
실제로 세션이 죽었을 때 28개가 보존되어 그 다음부터 재개할 수 있었다.

### 운영 요령

- **마운트 직후 바로 시작한다.** 유휴 상태로 두면 회수된다 (한 번 겪음).
- `colab exec` 는 긴 작업에서 타임아웃을 낸다. 작업 실패가 아니라 출력 대기 제한이므로,
  `nohup ... &` 로 백그라운드에 던지고 로그 파일을 따로 확인한다.
- 데이터셋은 작은 3개만 쓴다. 재시작 시 압축 해제 비용이 절반 이하가 된다.
  전체가 필요하면 `DATASETS="..." bash run_pipeline.sh`.

### 제외

**OOPS (1,197 클립)** — Zenodo 배포판에 영상이 없다. 파일이 12~16KB 껍데기뿐이고
(정상은 6~7MB), 안에 든 `cut.py` 가 원본을 직접 구해 자르라고 안내한다. 저작권 때문이다.

제외하니 분포가 오히려 균형 잡혔다 — OOPS 가 `fall` 과 `other` 에 몰려 있어
`fall` 비중이 34.6% 였다가 17.8% 로 내려갔다.

**LE2I(9GB) · OCCU(11GB) · MCFD(2.8GB) · UP_Fall(3GB)** — 지금은 보류.
세션 회수 대비로 재시작 비용을 낮추는 편이 낫다. 결과를 보고 필요하면 추가한다.

## 키포인트 정규화

단순히 좌표를 뽑는 것이 아니라 **카메라 불변 표현**으로 만든다.

1. 프레임 크기로 나눈다 → 해상도 무관
2. 엉덩이 중점을 원점으로 → 화면상 위치 무관
3. 몸통 길이(어깨~엉덩이)로 나눈다 → 카메라 거리 무관

스케일 기준을 몸통으로 잡은 이유: 사람이 서 있든 누워 있든 몸통 길이는 거의 일정하다.
바운딩 박스 높이로 나누면 누웠을 때 값이 폭증한다.

검증 결과 **해상도를 절반으로 줄이고 위치를 옮겨도 차이 0.0** 이었다.
서 있음(어깨 y=-1)과 누움(어깨 x=-1)도 명확히 구분된다.

이것이 AI Hub 베이스라인과의 핵심 차이다:

| | AI Hub | 본 연구 |
|---|---|---|
| 입력 차원 | 997,200 (얼굴 랜드마크가 84%) | 34/프레임 |
| 카메라 대응 | 위치별 모델 8개 | 좌표 표현 자체가 불변 |
| 시간 처리 | 600프레임 flatten (순서 소실) | 시퀀스 모델이 순서 학습 |

## 학습 설계

### split 은 피험자 단위

클립 단위보다 엄격하다. 같은 사람의 다른 클립이 train/test 에 갈리면
체형·습관이 누수되어 성능이 부풀려진다.

### 모델 선택 기준은 Recall

정확도가 아니다. 낙상을 놓치면 사람이 다치고, 오탐은 보호자가 확인하면 된다.
다만 오탐이 잦으면 알림을 무시하게 되므로(alarm fatigue) FPR 도 함께 본다.

### 클래스 가중치

`lying` 1.9%, `lie_down` 1.8% 로 소수 클래스가 있다. 가중치 없이 학습하면
이들을 통째로 무시하는 해로 수렴한다. 빈도의 역수 제곱근으로 보정한다.

### 태스크 3종

| 이름 | 클래스 | 용도 |
|---|---|---|
| `binary` | fall / 그 외 | 가장 단순한 낙상 감지 |
| `risk` | normal / fall / fallen | **기본** — 미동 위험까지 |
| `full` | 10클래스 | 전체 행동 인식 |

`risk` 가 본 연구의 목표에 맞다. `fallen`(넘어져 있음, 위험)과
`lying`(침대에 누움, 정상)이 다른 클래스로 들어간다.
