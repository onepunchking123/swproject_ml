# 학습 실행 순서도

_확정 사항 반영 · 2026-09-22_

## 결정된 것

| 항목 | 결정 |
|---|---|
| 검증 방식 | **피험자 5-fold 교차검증** |
| 저품질 클립 | **남긴다** (검출률 낮아도 제외하지 않음) |

## STEP 0 — 데이터 로드

```
1,194개 .npy  →  길이 제각각 (4~2423 프레임)
       ↓ 선형보간 리샘플
   (1194, 64, 17, 3)
       ↓ 라벨 매핑
   risk 3클래스:  normal 803 · fall 212 · fallen 179
```

**왜 고정 길이인가**: 클립 길이가 단서가 되면 안 된다. `fallen` 이 길다는
이유로 맞히면 실환경에서 무너진다.

**저품질 클립은 그대로 둔다.** 검출 실패 프레임은 0 으로 채워져 있고,
이것도 정보다 — 사람이 안 보이는 상황 자체가 패턴일 수 있다.

## STEP 1 — 모델 스크리닝

단일 split (train 13명 / val 3명 / test 3명) 으로 6개를 한 번씩 돌린다.
**목적은 정확한 성능이 아니라 순위 파악**이다. 5-fold 를 6개 모델에
전부 돌리면 30회라 낭비다.

| 모델 | 구조 | 특징 |
|---|---|---|
| **rule** | 몸통각도 + 하강속도 | 학습 없음. 이걸 못 이기면 딥러닝은 무의미 |
| cnn1d | Conv1d ×2 → pool | 지역 시간 패턴 |
| lstm | LSTM 2층 (128) | 순차 의존 |
| gru | GRU 2층 (128) | LSTM 경량화 |
| bilstm | BiLSTM + attention | 양방향 + 중요 프레임 가중 |
| stgcn | GCN+TCN 블록 ×2 | 골격 그래프 구조 명시 |

공통: 클래스 가중치(빈도 역수 √), AdamW, cosine 스케줄, early stop(patience 15),
**모델 선택 기준은 val Recall**.

→ 출력: 6개 순위표. 상위 3개를 STEP 2 로.

## STEP 2 — 피험자 5-fold

```
피험자 19명을 5조로 분할 (실측 확인: 모든 fold 에 3클래스 존재)

  fold0  4명 341클립 · fold1  4명 256 · fold2  4명 238
  fold3  4명 101     · fold4  3명 258

각 fold 를 한 번씩 test 로 → 5회 학습 → 평균 ± 표준편차
```

**왜 필요한가**: 피험자가 19명뿐이라 단일 split 의 test 는 3명이다.
그 3명이 누구냐에 따라 결과가 크게 흔들린다. 5-fold 는 모든 피험자가
한 번씩 test 에 들어가므로 **표준편차로 신뢰도를 보여줄 수 있다**.

fold3 이 101클립으로 작다. 피험자별 클립 수가 22~151개로 불균등한 탓이다.
이 fold 의 결과가 튀는지 따로 확인한다.

→ 출력: 3개 모델 × (평균±표준편차). 최종 1개 선정.

## STEP 3 — 데이터셋 leave-one-out

```
  edf + GMDCSA24 학습  →  caucafall 테스트
  edf + caucafall 학습 →  GMDCSA24 테스트
  GMDCSA24 + caucafall →  edf 테스트
```

환경·해상도·조명·피험자·카메라가 전부 바뀐다.
**"학습에 없던 환경에 설치해도 되는가"** 에 답한다.

STEP 2 결과와 비교하면 **사람이 바뀌는 것 vs 환경이 바뀌는 것 중
무엇이 더 어려운가**를 알 수 있다. 향후 데이터 수집 방향이 여기서 정해진다.

→ 출력: 3회 개별 수치 + 평균. 어느 환경에서 무너지는지 분석.

## STEP 4 — ablation

| 항목 | 비교 | 확인하려는 것 |
|---|---|---|
| 시퀀스 길이 | 32 / 64 / 128 | 짧은 낙상(2.4초)에 64가 적절한가 |
| 저품질 필터 | 전체 / 검출률 50%↑ / 80%↑ | 노이즈 제거가 실제로 도움되는가 |

저품질 필터링을 여기서 다루는 이유: 지금 거르면 "걸렀기 때문에 좋아졌다" 를
증명할 수 없다. **전부 넣고 학습한 뒤 비교해야 근거가 된다.**

## STEP 5 — 데이터 추가

1차 결과가 나온 뒤 LE2I(9GB) · OCCU(11GB) · MCFD(2.8GB) · UP_Fall(3GB) 추가.

```
zip 해제 → 키포인트 추출(수 시간) → manifest 갱신 → STEP 2·3 재실행
```

**이때 leave-one-out 조합이 3회 → 7회로 늘어** 환경 일반화 측정이
훨씬 탄탄해진다. 이것이 데이터 추가의 가장 큰 이득이다.

모델은 이미 정해져 있으므로 STEP 1 을 다시 할 필요가 없다.

## 평가 지표

모든 STEP 공통:

| 지표 | 우선순위 |
|---|---|
| **Recall** | **최우선** — 낙상을 놓치면 사람이 다친다 |
| **FPR** | 오탐이 잦으면 알림을 무시하게 된다 (alarm fatigue) |
| F1 / Precision / Accuracy | 참고 |
| Confusion matrix | `fallen` ↔ `lying` 혼동 여부 확인 |
| 파라미터 수 · 추론 시간 | 서비스 탑재 가능성 |
