# AI Hub 샘플 평가 계획

_샘플 데이터 확인 완료 · 2026-09-22_

## 확인된 구성

897MB · 영상 32개 · 프레임 라벨 포함.

| 장면 | 클래스 | 낙상 구간 | 장소 |
|---|---|---|---|
| 00003 | 전면낙상(FY) | 260~320f (4.3~5.3초) | 병원/병실 · 미끄러져 |
| 00015 | 측면낙상(SY) | 281~341f (4.7~5.7초) | 병원/병실 · 중심 잃고 |
| 00151 | 후면낙상(BY) | 375~435f (6.2~7.2초) | 병원/병실 · 중심 잃고 |
| 00047 | 비낙상(N) | 없음 | 병원/병실 |

**장면 4개 × 카메라 8대 = 32영상.** 전 영상 600프레임 / 60fps / 3840×2160.

### 평가 가능 여부

| 용도 | 가능 | 비고 |
|---|---|---|
| 파이프라인 동작 확인 | **가능** | 영상→YOLO→LSTM→판정 |
| 시각 보고서 | **가능** | 프레임 + 판정 카드 |
| **베이스라인 직접 비교** | **가능** | 같은 32영상으로 이미 측정 완료 |
| **카메라 편차 측정** | **가능** ★ | 같은 장면 8각도 — 핵심 실험 |
| 정량 성능 주장 | **불가** | 비낙상 1장면뿐, 통계적 의미 없음 |

**마지막을 분명히 해야 한다.** 이 32개로 "Recall 0.9 달성" 같은 주장은 할 수 없다.
비낙상이 8영상뿐이라 FPR 은 "8건 중 n건" 이 된다.

## 이 샘플의 진짜 가치 — 카메라 편차

정량 성능이 아니라 **편차**를 본다. 같은 장면을 8각도로 찍었으므로,
카메라만 바뀔 때 판정이 얼마나 흔들리는지 직접 측정된다.

AI Hub 베이스라인 실측 (`00151` 후면낙상):

| 카메라 | FALL 확률 |
|---|---|
| C5, C6, C8 | 0.98, 0.98, 1.00 |
| C1, C4, C7 | 0.77, 0.87, 0.87 |
| **C2, C3** | **0.23, 0.31** ← 판정 뒤집힘 |

**표준편차 0.30.** 같은 사건인데 각도에 따라 정반대 결론이 나온다.
C2 는 침대에 가려 사람이 거의 안 보이는 각도였다.

본 연구는 키포인트를 엉덩이 중점·몸통 길이로 정규화해 **좌표 표현 자체가
카메라 불변**이다 (해상도 절반+위치 이동에도 차이 0.0 검증됨).
따라서 **장면별 8각도 확률의 표준편차가 베이스라인보다 작아야 한다.**

이것은 32개 표본으로도 보일 수 있다 — 절대 성능이 아니라 일관성을 보는 것이므로.
**논문의 핵심 주장(카메라 독립성)에 대한 직접 증거**가 된다.

## 평가 설계

### 문제: 학습 데이터와 형식이 다르다

| | OmniFall (학습) | AI Hub 샘플 (평가) |
|---|---|---|
| 클립 | 구간별로 잘림 (중앙값 1.9초) | **600프레임 통짜 (10초)** |
| 라벨 | 클립 = 하나의 행동 | **프레임 구간으로 표시** |

모델은 짧은 클립을 받도록 학습됐는데 평가 영상은 10초짜리다.
**슬라이딩 윈도우**로 맞춘다.

### 방식: 슬라이딩 윈도우 판정

```
600프레임 영상
 ├─ 윈도우 0:   0~120f  → 모델 → (normal .9, fall .05, fallen .05)
 ├─ 윈도우 1:  30~150f  → 모델 → ...
 ├─ 윈도우 2:  60~180f  → 모델 → ...
 └─ ...                     stride 30f (0.5초)

→ 프레임별 확률 시계열
→ fall 확률이 임계값을 넘는 구간 = 예측 낙상 구간
→ 정답 구간(260~320f)과 비교
```

윈도우 120프레임(2초)은 낙상 지속 60프레임(1초)을 충분히 담는다.
stride 30프레임이면 영상당 17개 윈도우가 나온다.

### 지표 — 두 층위

#### (1) 영상 단위 (베이스라인 비교용)

베이스라인이 영상 단위로 판정했으므로 같은 기준으로 맞춘다.

```
영상에서 fall 확률 최댓값 > 임계값  →  "낙상" 판정

            예측
        낙상   비낙상
실제 낙상  TP     FN     ← 24영상 (3장면 × 8)
  비낙상   FP     TN     ←  8영상 (1장면 × 8)
```

| 방법 | Recall | FPR | 비고 |
|---|---|---|---|
| AI Hub RF (베이스라인) | **0.833** | **0.125** | 측정 완료 |
| 제안 파이프라인 | ? | ? | 이번에 측정 |

#### (2) 프레임 단위 (정밀도)

`fall_start_frame`/`fall_end_frame` 이 있으므로 가능하다. 베이스라인은 못 하는 평가다.

| 지표 | 정의 | 의미 |
|---|---|---|
| **감지 지연** | 예측 시작 − 정답 시작 | 얼마나 빨리 알아채는가 |
| 구간 IoU | 겹침 / 합집합 | 구간을 얼마나 정확히 잡는가 |
| 조기 경보 | 정답 시작 전 감지 여부 | 넘어지기 전 예측 가능한가 |

**감지 지연이 서비스에서 가장 중요한 지표 중 하나다.** 정확도가 같아도
3초 늦게 알리는 시스템은 쓸모가 떨어진다.

#### (3) 카메라 편차 ★

```
장면별로 8각도의 fall 확률 → 표준편차

              베이스라인   제안
00003 (FY)      0.??       ?
00015 (SY)      0.??       ?
00151 (BY)      0.30       ?      ← 실측됨
```

**표준편차가 작을수록 카메라에 강건하다.** 이 표가 논문의 핵심 그림이 된다.

## 실행 흐름

```
[선행] STEP 1~2 학습 완료 → 최종 모델 확보
              │
              ▼
┌─────────────────────────────────────────────┐
│ 1. 영상 → 키포인트                           │
│    32개 × 600프레임, YOLOv11-pose            │
│    scripts/extract_keypoints.py 재사용        │
│    (manifest 형식만 맞춰주면 됨)              │
└─────────────────────────────────────────────┘
              ▼
┌─────────────────────────────────────────────┐
│ 2. 슬라이딩 윈도우 추론                       │
│    120프레임 윈도우, stride 30                │
│    → 영상별 프레임 확률 시계열                │
└─────────────────────────────────────────────┘
              ▼
┌─────────────────────────────────────────────┐
│ 3. 지표 산출                                  │
│    영상단위 TP/FN/FP/TN + 프레임단위 지연·IoU │
│    + 장면별 카메라 표준편차                   │
└─────────────────────────────────────────────┘
              ▼
┌─────────────────────────────────────────────┐
│ 4. 시각 보고서 (HTML + PDF)                   │
│    make_report.py 확장                        │
└─────────────────────────────────────────────┘
```

### 보고서 형태

기존 `make_report.py` 를 확장한다. 영상 카드에 **확률 시계열 그래프**를 추가한다.

```
00003_H_A_FY_C2   [C2] [실제 전면낙상] [예측 낙상 ✓]
┌────┬────┬────┬────┬────┐
│ 0s │2.5s│5.0s│7.5s│10s │  ← 프레임 썸네일
└────┴────┴────┴────┴────┘
fall 확률 ▁▁▁▂▅█▇▃▁▁  ← 시계열 (정답 구간 260~320f 음영)
감지 지연 +12프레임 (0.2초)
```

**장면별 묶음 보기**: 같은 장면 8각도를 나란히 놓아 카메라별 판정 차이를
한눈에 보이게 한다. 베이스라인 보고서와 나란히 비교할 수 있다.
