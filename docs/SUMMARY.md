# 프로젝트 현황 총정리

_2026-09-24 기준 · **2026-09-28 갱신**: 배포 모델을 속도 채널(posvel) gru 로 교체 — 아래 수치는 교체 전 기록이며 최신 수치는 [results_velocity.md](results_velocity.md) · [ARCHITECTURE.md](ARCHITECTURE.md) 모델 카드_

## 한 줄 요약

**낙상 감지 파이프라인(YOLOv11-pose → 시계열 분류)을 구축해 AI Hub 공식 모델과
비교했다. 카메라 강건성과 Recall 에서 앞섰고, 오경보(FPR) 문제는 원인까지 규명했다.**

## 1. 완료된 것

### 1-1. 파이프라인 구축

```
영상 → YOLOv11-pose → 17 키포인트 → 카메라 불변 정규화
     → 64프레임 리샘플 → 시계열 모델 → normal / fall / fallen
```

**카메라 불변 정규화가 핵심 기여다.** 엉덩이 중점을 원점으로, 몸통 길이를 1 로
맞춘다. 검증 결과 **해상도를 절반으로 줄이고 위치를 옮겨도 차이 0.0** 이었다.

| | AI Hub 베이스라인 | 본 연구 |
|---|---|---|
| 입력 차원 | 997,200 (얼굴 랜드마크가 84%) | **20,400** (49배 작음) |
| 카메라 대응 | 위치별 모델 8개 | **단일 모델** |
| 시간 처리 | 600프레임 flatten (순서 소실) | 시퀀스 모델 |

### 1-2. 데이터

OmniFall 3개 데이터셋 · 1,194 클립 · 피험자 19명 · 키포인트 추출 완료.

```
walk 16.8% · fall 17.8% · fallen 15.0% · standing 13.1% · stand_up 11.8%
other 10.8% · sitting 7.8% · sit_down 3.2% · lying 1.9% · lie_down 1.8%
```

**데이터 오류 하나를 발견해 고쳤다** — edf 클립의 92.5%(459개)가 종료 시각
미적용으로 라벨 구간 밖 내용을 담고 있었다. 재자르기 후 프레임 중앙값이
1,197 → 90 이 됐고, **모든 모델의 성능이 개선됐다**.

### 1-3. 학습 결과 (STEP 1~3 완료)

**5-fold 교차검증** (피험자 단위, 이진 기준):

| 모델 | Recall | FPR | fallen 포착 |
|---|---|---|---|
| **bilstm** | 0.860 ± 0.091 | **0.121 ± 0.067** | **73.7%** |
| lstm | **0.891 ± 0.047** | 0.137 ± 0.064 | 47.5% |
| **gru** | 0.867 ± 0.066 | **0.112 ± 0.066** | **73.7%** |

**gru 또는 bilstm 을 권장한다.** lstm 은 Recall 이 가장 높지만 `fallen` 을
절반도 못 잡아 "넘어진 뒤 방치" 감지 목표에 약하다.

**데이터셋 leave-one-out** (환경 일반화):

| 조건 | Recall | FPR |
|---|---|---|
| 피험자 교차 | 0.86~0.89 | 0.11~0.14 |
| **환경 교차** | 0.78~0.84 | **0.19~0.21** |

**환경이 바뀌는 것이 사람이 바뀌는 것보다 어렵다.** 향후 데이터 수집은
피험자 수보다 환경 다양성을 우선해야 한다는 실용적 결론이다.

**규칙 기반의 한계도 확인했다** — 어느 환경에서도 `fallen` 을 0건 잡는다.
낙상 순간은 규칙으로 되지만 방치 상태 감지에는 시퀀스 모델이 필수다.

### 1-4. AI Hub 샘플 평가 (32영상)

| 항목 | AI Hub RF | 본 연구 |
|---|---|---|
| Recall | 0.833 | **0.917** |
| **FPR** | **0.125** | 0.750 |
| 카메라 표준편차 (00151) | 0.30 | **0.213** |

**카메라 강건성 입증**: 베이스라인이 판정을 뒤집었던 C2(0.23)·C3(0.31)에서
본 파이프라인은 0.59·0.89 로 유지한다.

**FPR 0.750 의 원인도 규명했다.** 비낙상 영상에서 피험자가 침대에 엎드린
자세(수평도 2.55)를 낙상으로 오판했다. 근본 원인은 학습 데이터의 `lying` 부족
(23개, 1.9%)이며, OmniFall 논문도 같은 현상을 보고한다.

## 2. 미완료 — 데이터 확장

`lying` 보강을 위해 OmniFall 4개 + 합성 12,000영상을 추가하려 했으나
**Colab 세션이 8회 회수되어 완료하지 못했다.**

진행 상황:

| 단계 | 상태 |
|---|---|
| 데이터 확보 (Drive 63GB) | ✓ |
| 합성 데이터 구조 파악 | ✓ 10클래스 × 1,200개 균등 |
| AV1 코덱 문제 발견·해결책 확인 | ✓ ffmpeg 변환 필요 |
| 키포인트 추출 | ✗ 세션 회수 |

**해결한 기술 문제들:**

- OpenCV 가 AV1 을 디코딩 못함 → ffmpeg `libdav1d` 로 변환
- Drive FUSE 가 작은 파일 1,194개 읽기에 극도로 느림 → `.npz` 묶음
- Colab CLI 0.6.0 버그 → 0.7.2 + `jupyter-kernel-client 0.9.0` 조합으로 해결
  (0.8.0 만 `JupyterSubprotocol` 이 없다)

**현재 CLI 는 정상 작동한다.** 마운트만 하면 재개 가능하다.

## 4. 논문 관점에서의 완결성

데이터 확장이 없어도 **주장과 근거가 갖춰져 있다.**

| 주장 | 근거 |
|---|---|
| 카메라 독립성 | 표준편차 0.30 → 0.213, 베이스라인이 뒤집힌 각도에서 유지 |
| 경량성 | 입력 997,200 → 20,400 차원 |
| 시퀀스 모델 필요성 | 규칙 기반은 `fallen` 0건 포착 |
| 환경 일반화 난이도 | 환경 교차가 피험자 교차보다 FPR 1.5~2배 |
| **한계 (FPR)** | **원인을 `lying` 부족으로 특정하고 해결책 제시** |

마지막 항목이 특히 중요하다. 실패를 보고만 한 것이 아니라 **원인 규명까지
했으므로** "향후 과제" 가 구체적이다.
