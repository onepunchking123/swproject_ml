# STEP 3 결과 — 데이터셋 leave-one-out

_2026-09-22 · 환경이 통째로 바뀔 때의 일반화 측정_

## 결과 (이진: 위험 = fall + fallen)

| 모델 | GMDCSA24 | caucafall | **edf** | 평균 |
|---|---|---|---|---|
| rule | 0.381/0.057 | 0.449/0.050 | 0.188/**0.122** | 0.339/0.076 |
| gru | 0.723/0.138 | 0.520/0.050 | 0.761/**0.765** | 0.668/0.318 |
| **lstm** | 0.729/0.145 | **0.694**/0.050 | 0.246/0.217 | 0.556/**0.137** |
| bilstm | **0.781**/0.175 | 0.592/0.100 | 0.696/**0.696** | 0.689/0.324 |

`Recall/FPR` 형식.

## edf 에서 모델이 무너진다 — 원인은 데이터 품질

gru 와 bilstm 의 edf FPR 이 **0.696~0.765** 다. 정상 클립의 70% 이상을
위험으로 오판한다는 뜻이며, 사실상 작동하지 않는다.

confusion matrix (gru@edf):

```
          normal   fall  fallen
normal        81    178      86    ← 정상 345건 중 264건 오판
fall          23     45      16
fallen        10     32      12
```

### 원인: edf 클립이 잘려 있지 않다

키포인트 프레임 수를 데이터셋별로 비교했다.

| 데이터셋 | 검출률 | **프레임 중앙값** | 클립 길이(manifest) |
|---|---|---|---|
| GMDCSA24 | 99.5% | 62 | 2.1초 |
| caucafall | 87.4% | 51 | 2.6초 |
| **edf** | 92.6% | **1,197** | 3.0초 |

edf 만 **20배** 길다. manifest 에는 3초로 적혀 있는데 실제로는 1,197프레임이다.

개별 파일을 확인하면 명확하다:

```
jianjun_..._0.000_3.054_...avi     manifest 3.1초 · 실제    92프레임  (30fps, 정상)
jianjun_..._100.999_104.480_...avi manifest 3.5초 · 실제 1,755프레임  (비정상)
jianjun_..._123.499_127.351_...avi manifest 3.9초 · 실제 1,080프레임  (비정상)
```

**시작 시각이 0 인 클립만 정상이고, 나머지는 시작 시각부터 영상 끝까지 들어있다.**
Zenodo 배포판의 자르기 과정에서 종료 시각이 적용되지 않은 것으로 보인다.

정량화하면:

| 데이터셋 | 자르기 실패 클립 |
|---|---|
| GMDCSA24 | 0 / 453 (0.0%) |
| caucafall | 0 / 258 (0.0%) |
| **edf** | **447 / 483 (92.5%)** |
| 전체 | 447 / 1,194 (37.4%) |

**전체 데이터의 37%가 라벨 구간 밖의 내용을 포함하고 있다.**

### 이것이 앞선 결과에 미친 영향

edf 클립은 3초짜리 라벨이 붙은 채 20초 분량의 내용을 담고 있다.
64프레임으로 리샘플하면 **라벨과 무관한 구간이 대부분을 차지**한다.

- STEP 1·2 에서 edf 가 train 에 섞여 있었으므로 **학습에도 노이즈로 작용**했다
- 5-fold 의 큰 표준편차(예: gru fold2 Recall 0.095)도 이것이 원인일 수 있다
- STEP 3 에서 edf 를 test 로 쓸 때 성능이 무너지는 것은 당연한 결과다

**따라서 STEP 1~3 의 절대 수치는 모두 재검토가 필요하다.**

## lstm 이 상대적으로 견딘다

edf 문제에도 불구하고 lstm 의 평균 FPR 은 0.137 로 gru(0.318)·bilstm(0.324)의
절반 이하다. STEP 2 의 관찰(lstm 이 가장 안정적)과 일치한다.

다만 이는 **lstm 이 edf 에서 낮은 Recall(0.246)로 "덜 반응한" 결과**이기도 하다.
edf 를 정리한 뒤 다시 판단해야 한다.

## fallen 포착 — 규칙의 한계 재확인

| 모델 | GMDCSA24 | caucafall | edf |
|---|---|---|---|
| **rule** | **0/77** | **0/48** | **0/54** |
| gru | 51/77 | 4/48 | 12/54 |
| lstm | 52/77 | 11/48 | 6/54 |
| bilstm | 54/77 | **27/48** | 9/54 |

**규칙은 어느 환경에서도 `fallen` 을 하나도 잡지 못한다.** 이진 판정만 하므로
구조적으로 불가능하다. "넘어진 뒤 방치" 감지에는 시퀀스 모델이 필수라는
STEP 2 의 결론이 환경을 바꿔도 유지된다.

## 조치 — edf 재처리가 필요하다

두 가지 방법이 있다.

| 방법 | 내용 | 비용 |
|---|---|---|
| **A. 키포인트 재자르기** | 기존 .npy 를 `start~end` 구간으로 슬라이스 | **수 분** |
| B. 영상 재추출 | 영상을 다시 잘라 키포인트 재추출 | 수십 분 |

**A 를 택한다.** 키포인트는 프레임 단위 배열이므로, manifest 의 `start`·`end` 와
fps 를 알면 해당 구간만 잘라낼 수 있다. 영상을 다시 볼 필요가 없다.

fps 는 데이터셋마다 다를 수 있으므로 `프레임수 / (end-start)` 로 역산하지 않고,
**정상 클립(start=0)에서 측정한 fps** 를 데이터셋 기준값으로 쓴다.
edf 의 정상 클립은 30fps 였다.

재처리 후 STEP 1~3 을 다시 돌린다. 학습 자체는 빠르므로(모델당 2~10초)
부담이 크지 않다.

## 한계

- 이 결과는 **edf 오염 상태에서 측정된 것**이므로 절대 수치로 인용할 수 없다
- 데이터셋이 3개뿐이라 leave-one-out 조합도 3회다. STEP 5 에서 데이터를
  추가하면 7회가 되어 일반화 측정이 탄탄해진다
