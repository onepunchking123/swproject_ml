# AI Hub 제공 모델 분석 (베이스라인)

_출처: 「낙상사고 위험동작 영상-센서 쌍 데이터」 `2.모델_doc` (2023.11 기준)_

데이터셋과 함께 공식 모델이 제공된다. 본 연구에 직접 사용하지는 않지만,
**같은 데이터셋에 대한 공식 베이스라인**이므로 비교 대상으로서 가치가 크다.

## 구성

데이터셋 이름이 "영상-**센서** 쌍"인 이유는 같은 낙상 장면을 카메라와 웨어러블
센서로 동시에 기록했기 때문이다. 따라서 모델도 세 갈래로 제공된다.

| 모델 | 입력 | 구성 | 센서 필요 |
|---|---|---|---|
| **영상 모델** | 영상만 | RandomForest × 8 × 2용도 = 16개 | 불필요 |
| 센서 모델 | 웨어러블 센서 | LSTM, CNN, ADA, GBC, MLP, RF, SVM, XGB + 앙상블 = 9개 | 필요 |
| 앙상블 | 영상 + 센서 | `FINAL_ENSEMBLE.ipynb` | 필요 |

> 매뉴얼 원문: "앙상블 모델 없이 영상, 센서 각각의 모델을 불러와 전처리 후 사용가능합니다"

**영상 모델만 단독으로 사용할 수 있다.** 카메라 기반인 본 연구와 관련 있는 것은
영상 모델뿐이다.

### 용도 구분

| 약어 | 의미 |
|---|---|
| **FNF** | 낙상유무 탐지 (Fall / Not Fall) — 이진 분류 |
| **FD** | 낙상유형 분류 (전면/후면/측면) |

모든 모듈이 이 둘로 나뉜다. `FINAL_ENSEMBLE.ipynb` 는 FD 기준으로 작성되어 있다.

## 실행 방법

두 가지 경로가 있다. Docker 는 환경 구성을 건너뛰는 편의 수단일 뿐 필수가 아니다.

### A. 소스코드 직접 실행 (Apple Silicon 에 권장)

```bash
python3.9 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
```

`1.모델소스코드` 폴더에 `FINAL_ENSEMBLE.ipynb`, `util/util_nia_project.py`,
전처리 코드, RandomForest 학습 노트북이 들어 있다.

### B. Docker

```bash
docker load -i fnf_docker.tar          # 낙상유무 탐지
docker images
docker run -it --oom-kill-disable <이미지명>
```

문서에 기재된 주의사항:

- RAM/용량 부족 시 OOM 발생 가능 → `--oom-kill-disable`
- **test size 는 500~700개를 넘지 않는 것이 좋다**
- 용량 문제가 있으면 tar 를 쓰지 말고 이미지를 처음부터 빌드하는 편이 낫다

맥북 M3(Apple Silicon)에서는 x86 이미지일 경우 에뮬레이션으로 느려질 수 있으므로
A 방식을 권한다.

## 실제 구조 (소스코드 분석 결과)

문서만으로는 알 수 없었던 실제 파이프라인을 코드에서 확인했다.
**영상 모델도 키포인트를 사용한다** — MediaPipe 로 추출한다.

```
영상(mp4) → MediaPipe Holistic → 키포인트 .npy 저장
                                      ↓
                        600 프레임 시퀀스로 묶기
                                      ↓
                   flatten (600 × 1,662 = 997,200 차원)
                                      ↓
                        SMOTE 오버샘플링
                                      ↓
              RandomForest (n_estimators=100, max_depth=80, entropy)
```

### 입력 차원의 정체

학습된 `.pkl` 을 열어 확인한 `n_features_in_` 은 **997,200** 이다.

```
997,200 ÷ 600 프레임 = 1,662 차원/프레임
```

1,662 는 MediaPipe Holistic 의 전체 랜드마크다:

| 부위 | 계산 | 차원 |
|---|---|---|
| pose | 33 × 4 (x, y, z, visibility) | 132 |
| face | 468 × 3 | 1,404 |
| 왼손 | 21 × 3 | 63 |
| 오른손 | 21 × 3 | 63 |
| **합계** | | **1,662** |

**낙상 판단에 얼굴 468점을 쓰고 있다.** 전체의 84%가 얼굴 랜드마크다.
낙상은 몸통과 사지의 움직임이지 표정이 아니므로, 이는 불필요한 차원이다.

이것이 만드는 문제:

- **차원의 저주** — 997,200 차원에 RandomForest 는 과도하다
- **메모리 폭증** — 샘플 700개면 700 × 997,200 × 8바이트 = 약 5.6GB.
  문서의 "test size 500~700 권장", "OOM 주의" 경고가 여기서 나온다
- **엎어진 자세에서 얼굴 랜드마크가 0으로 채워진다** — 그 결측 패턴 자체가
  낙상 신호로 학습됐을 가능성이 있다 (검증 필요)

본 연구의 YOLOv11-pose 는 17 키포인트 × 2 = 34 차원이다.
600 프레임이어도 20,400 차원으로 **약 49배 작다.**
경량화와 실시간 처리 가능성을 주장할 근거가 된다.

### 확인된 모델 파일

| 구분 | 파일 | 클래스 | 입력 차원 |
|---|---|---|---|
| 낙상유무 (FNF) | `FNF_RF_SMOTE_CAM_1~8.pkl` | 2 (Fall/NonFall) | 997,200 |
| 낙상유형 (FD) | `RF_SMOTE_CAM_1~8.pkl` | 3 (FY/BY/SY) | 997,200 |

모두 `RandomForestClassifier(n_estimators=100, max_depth=80, criterion='entropy')`.

라벨 약어: **FY** 전면낙상, **BY** 후면낙상, **SY** 측면낙상, **NF/N** 비낙상.

## 본 연구와의 차이

| | AI Hub 영상 모델 | 본 연구 (YOLOv11-pose + 시계열) |
|---|---|---|
| **키포인트 추출** | MediaPipe Holistic (1,662차원) | YOLOv11-pose (34차원) |
| **카메라 위치** | 위치별 모델 8개 (고정 전제) | 위치 독립 |
| **시간 정보** | RandomForest — 정적 분류기 | LSTM/GRU/ST-GCN — 시퀀스 학습 |
| **입력 차원** | 997,200 | 20,400 (약 49배 작음) |

세 가지 한계가 실서비스 적용을 어렵게 한다.

1. **시계열 구조가 소실된다.** 600 프레임 × 1,662 차원을 하나의 벡터로
   flatten 하므로, RandomForest 는 각 차원을 독립 특징으로 볼 뿐
   "3번 프레임 다음에 4번 프레임" 이라는 순서 관계를 학습하지 못한다.
2. **카메라 위치별로 모델이 나뉜다.** 가정·요양시설마다 카메라 설치 위치가
   다른데, 학습에 없던 각도에서는 어느 모델을 쓸지도 불분명하고 성능도 보장되지 않는다.
3. **RandomForest 는 시간 구조를 약하게 다룬다.** 낙상은 "서있음 → 누움" 의
   전이인데, 정적 분류기는 미리 계산한 통계 특징에 의존한다. 시퀀스 자체를
   학습하지 못한다.

다만 **낙상 판단 자체는 수행하며 정확도도 낮지 않을 것으로 보인다.**
문제는 정확도가 아니라 실환경 일반화다.

## 논문에서의 활용

같은 데이터셋에 대한 **공식 베이스라인과 직접 비교**할 수 있다는 것은
강력한 근거가 된다. 논지는 다음과 같이 정리된다.

> AI Hub 공식 베이스라인은 MediaPipe Holistic 으로 997,200 차원 특징을 추출해
> 카메라 위치별 RandomForest 8개로 분류한다. 600 프레임을 flatten 하므로 시간
> 순서가 소실되고, 특징의 84%가 낙상과 무관한 얼굴 랜드마크이며, 고정 카메라를
> 전제한다. 본 연구는 YOLOv11-pose 기반 2단계 파이프라인으로 입력 차원을 약 49배
> 줄이고, 시퀀스 모델로 시간 구조를 명시적으로 학습하며, 카메라 위치 독립성을
> 확보한다.

비교표 양식:

| 방법 | 입력 차원 | 시간 모델링 | 카메라 독립 | 센서 | Recall | FPR |
|---|---|---|---|---|---|---|
| AI Hub RF (영상) | 997,200 | ✗ flatten | ✗ | ✗ | | |
| AI Hub 앙상블 | 997,200+센서 | ✗ | ✗ | ✓ | | |
| 제안: YOLOv11-pose + 규칙 | 34/프레임 | 윈도우 | ✓ | ✗ | | |
| 제안: YOLOv11-pose + LSTM | 20,400 | ✓ 순차 | ✓ | ✗ | | |
| 제안: YOLOv11-pose + ST-GCN | 20,400 | ✓ 시공간 | ✓ | ✗ | | |

공정한 비교를 위해 동일한 test split 을 사용해야 한다.

## 실행 절차

### 환경

영상 RF 만 쓸 경우 TensorFlow 는 불필요하다 (센서 LSTM/CNN 전용).

```bash
uv venv --python 3.11 venv_aihub
uv pip install --python venv_aihub/bin/python "scikit-learn==1.3.2" "numpy<2" joblib
uv pip install --python venv_aihub/bin/python mediapipe opencv-python
```

`scikit-learn` 은 학습 시 버전(1.3.2)과 맞춰야 `.pkl` 로드 시 경고·오류가 없다.

### 추론 파이프라인

원 소스는 로컬 경로가 하드코딩되어 있어 재작성이 필요하다. 흐름은 다음과 같다.

1. 영상에서 카메라 번호(C1~C8) 판별 → 해당 `.pkl` 선택
2. MediaPipe Holistic 으로 프레임별 1,662 차원 키포인트 추출
3. 600 프레임 확보 (미달 시 건너뜀)
4. `reshape(1, 997200)` 후 `model.predict()`
5. Confusion matrix / classification report 산출

메모리 주의: 샘플 하나가 997,200 × 8바이트 = 약 8MB.
700개면 5.6GB 이므로 배치로 나눠 처리한다.
