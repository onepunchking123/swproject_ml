# AI Hub 샘플 파이프라인 평가

_2026-09-22 · 영상 32개(장면 4 × 카메라 8) · 모델 gru_

```
영상(600f) → YOLOv11-pose → 키포인트(카메라 불변 정규화)
           → 슬라이딩 윈도우(120f, stride 30) → gru → 프레임별 확률
```

## 베이스라인 대비

같은 32영상에 대한 AI Hub 공식 모델(RandomForest, 카메라별 8개) 측정값과 비교한다.

| 항목 | AI Hub RF | **제안 파이프라인** |
|---|---|---|
| Recall | 0.833 | **0.917** |
| FPR | **0.125** | 0.750 |
| Precision | 0.952 | 0.786 |
| 놓친 낙상 | 4 / 24 | **2 / 24** |
| 입력 차원 | 997,200 | **20,400** (49배 작음) |
| 모델 수 | 8 (카메라별) | **1** |
| 감지 지연 측정 | 불가 (영상 단위) | **가능** |

**Recall 은 올랐지만 FPR 이 크게 나빠졌다.** 비낙상 8영상 중 6개를 낙상으로 오판한다.

## FPR 0.750 의 원인 — 침대에 엎드린 자세

비낙상 장면(00047)의 위험 확률:

```
C1 0.95 · C2 0.93 · C8 0.90 · C3 0.87 · C7 0.71 · C4 0.61 · C5 0.46 · C6 0.41
```

해당 영상의 60프레임 지점을 확인하니 **피험자가 침대에 엎드려 상체를 숙이고 있다.**
키포인트 수평도(몸통이 누운 정도)를 보면 명확하다.

| 구간 | 수평도 |
|---|---|
| 0~99f | 1.10 |
| **100~199f** | **2.55** |
| 200~299f | 0.79 |
| 400~599f | 0.15 |

수평도 2.55 는 몸통이 거의 수평이라는 뜻이다. 모델은 이를 낙상으로 판정했다.

### 근본 원인: 학습 데이터의 `lying` 부족

이것은 정확히 **`fallen`(바닥에 넘어짐, 위험) vs `lying`(침대에 누움, 정상)** 의
구분 문제다. OmniFall 라벨은 이 둘을 구분하지만, 학습 데이터에서

```
fallen  179개 (15.0%)
lying    23개 ( 1.9%)   ← 너무 적다
```

`lying` 이 1.9% 뿐이라 모델이 "수평 자세 = 위험" 으로 학습했다.
침대·소파에서의 정상적인 누운 자세를 충분히 보지 못한 것이다.

**이 실패는 모델 구조가 아니라 데이터 구성의 문제다.**

## 카메라 편차 — 핵심 비교

같은 장면을 8각도로 찍었으므로 카메라만 바뀔 때의 판정 흔들림을 직접 잴 수 있다.

| 장면 | 클래스 | 평균 | **표준편차** |
|---|---|---|---|
| 00003 | 전면낙상 | 0.895 | **0.120** |
| 00015 | 측면낙상 | 0.779 | 0.242 |
| **00151** | **후면낙상** | 0.802 | **0.213** |
| 00047 | 비낙상 | 0.730 | 0.201 |

**베이스라인은 장면 00151 에서 표준편차 0.30 이었다** (C5 0.98 vs C2 0.23 —
같은 낙상에 정반대 판정). 제안 파이프라인은 **0.213** 으로 29% 낮다.

장면 00151 카메라별 비교:

| 카메라 | 베이스라인 | 제안 |
|---|---|---|
| C1 | 0.77 | 0.92 |
| **C2** | **0.23** ← 판정 뒤집힘 | **0.59** |
| C3 | 0.31 | 0.89 |
| C4 | 0.87 | 0.91 |
| C5 | 0.98 | 0.88 |
| **C6** | 0.98 | **0.32** |
| C7 | 0.87 | 0.97 |
| C8 | 1.00 | 0.93 |

베이스라인이 무너졌던 C2·C3 에서 제안 파이프라인은 0.59·0.89 로 판정을 유지한다.
다만 C6 에서는 0.32 로 낮아, 취약한 각도가 달라졌을 뿐 완전히 해소되지는 않았다.

전면낙상(00003)은 표준편차 0.120 으로 가장 안정적이다.

## 감지 지연 — 베이스라인이 못 하는 평가

AI Hub 라벨의 `fall_start_frame`/`fall_end_frame` 을 이용했다.
베이스라인은 영상 단위 판정이라 이 측정이 불가능하다.

| 항목 | 값 |
|---|---|
| 중앙값 | **-11프레임** (-0.18초) |
| 범위 | -315 ~ +135프레임 |
| 정답 구간 이전 감지 | **12 / 22건** |

**중앙값이 음수**다. 절반 이상의 경우 정답 낙상 구간이 시작되기 **전에** 위험을 감지한다.

다만 이는 양날이다 — 넘어지기 직전의 자세 변화를 포착한 것일 수도 있고,
낙상과 무관한 구간에서 이미 높은 확률을 내고 있었을 수도 있다.
FPR 0.750 을 감안하면 후자의 비중이 클 것으로 보인다.

## 임계값 조정

임계값을 올리면 FPR 이 개선되지만 Recall 을 잃는다.

| 임계값 | Recall | FPR | F1 |
|---|---|---|---|
| 0.50 | **0.917** | 0.750 | 0.846 |
| 0.75 | 0.750 | 0.500 | 0.783 |
| **0.90** | 0.667 | **0.250** | 0.762 |
| 0.95 | 0.250 | 0.000 | 0.400 |

**어느 임계값에서도 베이스라인(0.833/0.125)을 동시에 넘지 못한다.**
임계값 조정으로 해결될 문제가 아니라 학습 데이터를 고쳐야 한다.

## 결론

| | 평가 |
|---|---|
| 카메라 강건성 | **개선됨** — 표준편차 0.30 → 0.213 |
| 낙상 감지(Recall) | **개선됨** — 0.833 → 0.917 |
| 오경보(FPR) | **악화** — 0.125 → 0.750 |
| 경량성 | **개선됨** — 입력 49배 작음, 모델 8개 → 1개 |
| 감지 지연 측정 | **새로 가능** |

**핵심 주장(카메라 독립성)은 입증됐으나, `lying` 데이터 부족으로 실용성이 떨어진다.**

### 개선 방향

1. **`lying`·`sitting` 데이터 보강** — 침대·소파에서의 정상 자세를 늘린다.
   Drive 에 있는 LE2I·OCCU·MCFD·UP_Fall 추가가 직접적 해결책이다.
2. **위치 맥락 추가** — 침대/소파 ROI 를 정의해 그 안에서의 수평 자세는
   감점한다. 규칙과 모델의 하이브리드.
3. **지속 시간 조건** — 낙상 후 `fallen` 이 일정 시간 지속될 때만 경보.
   침대에 잠깐 엎드린 것과 구분된다.
